# Справочник CLI

```text
rustore-mcp <команда> [флаги]
```

| Команда | Назначение |
| --- | --- |
| [`connect`](#connect) | Подключить сервер к Claude Code или Codex одной командой. |
| [`serve`](#serve) | Запустить MCP-сервер через stdio или по HTTP ([`--http`](#serve---http)). |
| [`auth`](#auth) | Управлять ключами RuStore API профилей: `login`, `status`, `logout`. |
| [`tools`](#tools) | Показать и проверить пользовательские инструменты из `tools.toml`: `list`, `check`. |

`rustore-mcp --version` печатает версию, `rustore-mcp <команда> --help` — справку по команде.

## Профили

Профиль — имя, под которым хранятся ключ RuStore API одной компании и настройки сервера. Профиль по умолчанию — `default`, другой выбирается флагом `--profile`. Для каждого ключа компании используйте свой профиль.

- **Ключ** — keyId и приватный ключ RSA — только в системном хранилище: macOS Keychain, Secret Service в Linux, Credential Manager в Windows. Сервис `dev.filipov.rustore-mcp`, учётная запись — имя профиля; в Windows ключ хранится байтами UTF-8 и, если не помещается в одну запись, частями (`<профиль>/part-2` и далее). Ключ принимается только из файла или stdin, не из аргументов командной строки и не из переменных окружения; в `profiles.toml` он не пишется и не печатается ни одной командой. Команды показывают только замаскированный keyId (`abcd***wxyz`) и размер ключа.
- **Токен** RuStore API (JWE, живёт несколько минут) сервер получает сам: подписывает запрос `POST /public/auth/` приватным ключом (SHA512withRSA) и держит токен только в памяти процесса, обновляя его до истечения срока.
- **Настройки** (без ключа) — в `~/.config/rustore-mcp/profiles.toml`; в Linux учитывается `XDG_CONFIG_HOME`, в Windows файл лежит в `%APPDATA%\rustore-mcp\profiles.toml`. Файл создают `connect` и `auth login`:

  ```toml
  [profiles.default]
  client = "codex"                 # клиент, в котором профиль зарегистрирован через connect
  packages = ["com.example.app"]   # имена пакетов по умолчанию, их видит агент; необязательно
  allow_write = false
  allow_destructive = false
  toolsets = []
  ```

`allow_destructive = true` подразумевает запись: при сохранении профиля `allow_write` выставляется тоже.

Имя профиля: 1–64 символа из `A-Z`, `a-z`, `0-9`, `.`, `_`, `-`, не начинается с `-`.

### Ключ RuStore API

Ключ создаёт владелец или администратор компании в консоли RuStore: «Компания → RuStore API». При создании отметьте методы API, которые нужны агенту, и приложения, с которыми ключ может работать, и сохраните приватный ключ в файл: консоль показывает его один раз. Файл ключа для `rustore-mcp` — один из двух форматов:

- JSON `{"keyId": "<keyId>", "privateKey": "<приватный ключ>"}`;
- только приватный ключ — текст Base64 из консоли (DER PKCS#8 или PKCS#1) или PEM (`BEGIN PRIVATE KEY`, `BEGIN RSA PRIVATE KEY`); keyId тогда передаётся флагом `--key-id` или, в терминале, ответом на вопрос.

Ключ RSA короче 2048 бит не принимается. Файл ключа больше 16 КиБ — ошибка.

### Linux без Secret Service

Запасного файлового хранилища нет. Если в сессии нет демона Secret Service (`org.freedesktop.secrets` на сессионной шине D-Bus), команды `auth` завершаются ошибкой с подсказкой. Запустите демон хранилища: GNOME Keyring, KDE Wallet или KeePassXC с интеграцией Secret Service. На машине без графической сессии можно поднять шину и разблокированное хранилище вручную:

```bash
dbus-run-session -- sh
# внутри новой оболочки; пароль хранилища читается из stdin
gnome-keyring-daemon --unlock --components=secrets
```

## connect

```text
rustore-mcp connect <claude-code|codex> [флаги]
```

Подключает сервер к MCP-клиенту: создаёт или обновляет профиль, сохраняет ключ RuStore API и после подтверждения добавляет сервер в конфигурацию клиента. Ключ не проходит через агента и не попадает в конфигурацию клиента: туда записывается только команда

```text
<путь к rustore-mcp> serve --profile <профиль> [--allow-write] [--allow-destructive] [--toolsets <a,b>] [--dynamic-toolsets]
```

| Флаг | По умолчанию | Назначение |
| --- | --- | --- |
| `--profile <имя>` | `default` | Профиль: один профиль — один ключ компании. |
| `--name <имя>` | `rustore` для профиля `default`, `rustore-<профиль>` для остальных | Имя сервера в конфигурации клиента: 1–17 символов из `A-Z`, `a-z`, `0-9`, `_`, `-`. Предел 17 символов нужен, чтобы полное имя инструмента `mcp__<сервер>__<инструмент>` укладывалось в 64 символа. |
| `--scope <user\|project>` | `user` | `user` — для всех проектов пользователя; `project` — в `.mcp.json` текущего каталога (только Claude Code). |
| `--allow-write` | выкл. | Разрешить инструменты записи. |
| `--allow-destructive` | выкл. | Разрешить инструменты удаления и публикации; включает `--allow-write` (в профиль сохраняются оба флага). |
| `--toolsets <a,b,…>` | набор `serve` по умолчанию | Наборы инструментов; неизвестный набор — ошибка. |
| `--dynamic-toolsets` | выкл. | [Динамические наборы](tools.md#динамические-наборы): при запуске только поиск, запросы и управление наборами, остальное агент включает сам. Нужен клиент, который перечитывает список инструментов по уведомлению. |
| `--key-file <путь>` | спросить в терминале | Файл ключа RuStore API ([форматы](#ключ-rustore-api)). |
| `--key-id <ID>` | из файла или вопрос | keyId ключа, если в файле только приватный ключ. |
| `--package <имя>` | из профиля | Имя пакета приложения по умолчанию (флаг повторяется); его видит агент. |
| `-y`, `--yes` | выкл. | Не задавать вопросов «да/нет»: оставить рабочий сохранённый ключ и записать конфигурацию клиента. |
| `--no-verify` | выкл. | Сохранить ключ без проверки запросом к RuStore API. |

Шаги:

1. **Ключ.** Если в хранилище уже есть ключ профиля и он проходит проверку, `connect` предлагает его оставить (с `--yes` — оставляет). Иначе читает файл `--key-file` или, в терминале, спрашивает путь к нему (и keyId, если в файле только приватный ключ). Ключ проверяется: сервер получает токен и запрашивает список приложений `GET /public/v1/application`. Если проверка не прошла, ничего не сохраняется, а сообщение подсказывает, что отметить у ключа в консоли RuStore.
2. **Профиль.** В `profiles.toml` записываются клиент, имена пакетов, флаги доступа, наборы инструментов и `dynamic_toolsets` из флагов `connect` (флаги доступа, наборы и `dynamic_toolsets` перезаписываются при каждом запуске).
3. **Конфигурация клиента.** `connect` показывает, что именно будет записано, и спрашивает подтверждение; при отказе (или без ответа) конфигурация не меняется, а ключ и профиль остаются.
   - **Claude Code** — через его CLI: `claude mcp add --scope <scope> <имя> -- <путь> serve --profile <профиль> …`. Файлы Claude Code напрямую не правятся. Если сервер с таким именем уже есть и запускает `rustore-mcp`, он заменяется (`claude mcp remove` и снова `add`) после подтверждения.
   - **Codex** — таблица `[mcp_servers.<имя>]` в `$CODEX_HOME/config.toml` (по умолчанию `~/.codex/config.toml`):

     ```toml
     [mcp_servers.rustore]
     command = "/opt/homebrew/bin/rustore-mcp"
     args = ["serve", "--profile", "default", "--allow-write"]
     ```

     Остальные записи, комментарии и форматирование файла сохраняются; запись с тем же именем заменяется на месте.

   Запись с тем же именем, которая запускает другой сервер, а не `rustore-mcp`, заменяется только после явного ответа в терминале; с `--yes` `connect` завершается ошибкой и ничего не меняет. Чтобы подключить сервер рядом с ней, выберите другое имя через `--name`.
4. **Файл ключа.** В терминале `connect` в конце предлагает удалить исходный файл ключа (по умолчанию — нет: консоль RuStore показывает приватный ключ только при создании, и файл может быть единственной копией). Без терминала файл не трогается.

После подключения перезапустите клиент. В конфигурацию записывается абсолютный путь к запущенному бинарнику без раскрытия symlink: при установке через Homebrew путь `bin/rustore-mcp` переживает обновления.

## serve

```text
rustore-mcp serve [--profile <имя>] [--allow-write] [--allow-destructive]
                  [--toolsets <набор,...>|all] [--dynamic-toolsets]
                  [--tools-file <путь>]... [--allow-path <каталог>]...
                  [--timeout <секунды>] [--max-response-bytes <байты>]
                  [--log-level <уровень>] [--status]
```

Запускает MCP-сервер через stdio: MCP-клиент (Claude Code, Codex и другие) запускает команду сам и общается с ней через stdin и stdout. HTTP-режим описан ниже, в [`serve --http`](#serve---http). Каждая операция RuStore API из встроенной спецификации — отдельный инструмент; имя инструмента — `operationId` операции в snake_case (`list_versions`, `create_draft_version`, `reply_to_review`). Поверх операций есть [составные инструменты](tools.md#составные-инструменты) (`upload_build`, `release_submit`, `release_rollout`, `reviews_summary` и другие), а всегда доступны `api_search` (поиск по всем операциям) и `api_request` (запрос к любому пути API в пределах уровня доступа), см. [MCP-инструменты](tools.md#api_search-и-api_request).

Ключ RuStore API берётся только из профиля (`--profile`, по умолчанию `default`) в системном хранилище; имена пакетов по умолчанию — из `profiles.toml`. Если ключа нет, сервер не запускается и подсказывает команду `auth login`. Токен RuStore API сервер получает по ключу перед первым запросом, держит только в памяти, обновляет до истечения срока, а после ответа `401` один раз повторяет запрос с новым токеном. Ни ключа, ни токена в аргументах инструментов нет.

| Флаг | Назначение |
| --- | --- |
| `--profile <имя>` | Профиль с ключом RuStore API. |
| `--allow-write` | Регистрировать инструменты, которые создают и меняют данные. |
| `--allow-destructive` | Регистрировать и удаляющие инструменты; включает запись. |
| `--toolsets <набор,...>` | Наборы инструментов через запятую или `all`. С `--dynamic-toolsets` — наборы, включённые при запуске. |
| `--dynamic-toolsets` | [Динамические наборы](tools.md#динамические-наборы): при запуске только `api_search`, `api_request`, `list_toolsets`, `enable_toolset`, `disable_toolset` и пользовательские инструменты; наборы агент включает сам. Не сочетается с `--http`. |
| `--tools-file <путь>` | Дополнительный файл [пользовательских инструментов](tools.md#пользовательские-инструменты) в формате `tools.toml`; флаг повторяется. В HTTP-режиме читаются только эти файлы. |
| `--allow-path <каталог>` | Дополнительный каталог для локальных файлов; флаг повторяется. |
| `--timeout <секунды>` | Таймаут одного запроса к API, по умолчанию 60. |
| `--max-response-bytes <байты>` | Предел ответа API, который возвращается агенту, по умолчанию 262144 (256 КиБ). Больший ответ — ошибка с подсказкой сузить запрос. С [фильтром `jq`](tools.md#фильтр-ответа-jq) предел относится к результату фильтра. |
| `--log-level <уровень>` | Уровень или фильтр логов в stderr (`info`, `debug`, `rustore_mcp_core=debug`). Без флага — переменная `RUST_LOG`, без неё — `warn`. |
| `--status` | Показать действующие настройки и выйти, не запуская сервер. |

### Уровни доступа и наборы

Без флагов сервер работает только на чтение с наборами `apps`, `releases` и `reviews`. Флаги командной строки важнее настроек профиля: без `--allow-write` и `--allow-destructive` уровень берётся из `allow_write` и `allow_destructive` профиля, без `--toolsets` — наборы из `toolsets` профиля, без `--dynamic-toolsets` — настройка `dynamic_toolsets` профиля. Неизвестный набор — ошибка запуска со списком допустимых.

Пользовательские инструменты читаются при запуске из `tools.toml` рядом с `profiles.toml`, если файл есть, и из файлов `--tools-file`. Ошибка в файле — ошибка запуска; проверить файлы заранее можно командой [`tools check`](#tools).

Что входит в уровни и наборы, как устроены аргументы и ответы инструментов, `api_search` и `api_request` — в [MCP-инструментах](tools.md). Вырезание учётных данных из ответов и правила для локальных файлов — в [Безопасности](security.md).

### serve --status

```text
rustore-mcp serve --status [--profile <имя>] [--allow-write] [--allow-destructive] [--toolsets ...]
                  [--dynamic-toolsets] [--tools-file <путь>]...
```

Печатает, с какими настройками запустился бы сервер с теми же флагами: профиль, ключ (замаскированный keyId и размер RSA, без значения), имена пакетов, уровень доступа и откуда он взят (флаги, профиль или по умолчанию), наборы, включены ли динамические наборы, число инструментов, сколько пользовательских инструментов определено и зарегистрировано (и путь к `tools.toml`), разрешённые каталоги и путь к `profiles.toml`. Сервер не запускается, к API запросов нет. `--allow-destructive` без `--allow-write` показывается как `destructive (read, write and delete tools; …)` с источником уровня.

### serve --http

```text
rustore-mcp serve --http --access-tokens <файл> [--profile <имя> | --key-file <файл> [--key-id <ID>]]
                  [--listen <IP:порт>] [--allowed-host <имя>]... [--allowed-origin <origin>]...
                  [--max-request-bytes <байты>] [--allow-write] [--allow-destructive]
                  [--toolsets <набор,...>|all] [--tools-file <путь>]... [--timeout <секунды>]
                  [--max-response-bytes <байты>] [--log-level <уровень>]
```

Запускает тот же сервер как HTTP-сервис (Streamable HTTP без сессий): `POST /mcp` и `GET /health`, по умолчанию на `127.0.0.1:8766`. Ключ RuStore API остаётся на сервере: из системного хранилища профиля `--profile` или из файла секрета `--key-file` (контейнеры). Клиенты MCP передают только свой токен доступа в `Authorization: Bearer <токен>`; в файле `--access-tokens` — SHA-256 каждого токена, его имя, уровень доступа и наборы. Флаги `--allow-write` и `--allow-destructive` задают потолок для токенов. Локальные файлы выключены; `--allow-path`, `--status` и `--dynamic-toolsets` вместе с `--http` — ошибка.

| Флаг | Назначение |
| --- | --- |
| `--http` | Режим HTTP вместо stdio. |
| `--access-tokens <файл>` | TOML с токенами доступа клиентов: обязателен. |
| `--key-file <файл>` | Файл секрета с ключом RuStore API вместо хранилища профиля: только Unix, обычный файл (или ссылка на него) с правами 0600 или 0400. |
| `--key-id <ID>` | keyId для `--key-file`, в котором только приватный ключ. |
| `--listen <IP:порт>` | Адрес и порт, по умолчанию `127.0.0.1:8766`. |
| `--allowed-host <имя>` | Дополнительное допустимое значение `Host` (`имя` или `имя:порт`); флаг повторяется. |
| `--allowed-origin <origin>` | Допустимый `Origin` браузерного клиента; флаг повторяется. |
| `--max-request-bytes <байты>` | Предел тела запроса MCP, по умолчанию 1048576 (1 МиБ). |

Файл токенов доступа:

```toml
[[tokens]]
name = "ci"                     # имя для логов: [A-Za-z0-9._-], до 64 символов
sha256 = "<64 hex-символа>"     # SHA-256 токена, сам токен в файле не хранится
access = "read"                 # read, write или destructive; не выше флагов сервера
toolsets = ["<набор>"]          # необязательно: наборы этого токена
```

Токен можно создать командой `openssl rand -hex 32`, его хеш — `printf %s "$TOKEN" | sha256sum`. Коды ответов, Docker-образ, `compose.yaml` и подключение клиентов — в [HTTP-режиме](http.md).

## auth

### auth login

```text
rustore-mcp auth login [--profile <имя>] [--key-file <файл> | --key-stdin] [--key-id <ID>]
                       [--package <имя>]... [--no-verify]
```

| Флаг | Назначение |
| --- | --- |
| `--key-file <файл>` | Файл ключа RuStore API ([форматы](#ключ-rustore-api)). Без флага и без `--key-stdin` путь спрашивается в терминале. |
| `--key-stdin` | Прочитать ключ из stdin (например, из менеджера паролей). Вопросов нет: keyId передайте в файле или флагом `--key-id`. |
| `--key-id <ID>` | keyId, если в файле только приватный ключ. |
| `--package <имя>` | Имя пакета приложения по умолчанию; флаг повторяется и заменяет список в профиле. |
| `--no-verify` | Сохранить ключ без проверки (без сети). |

Сохраняет ключ RuStore API профиля:

1. Ключ читается из файла, из stdin или по пути, который спрашивается в терминале; печатаются замаскированный keyId и размер RSA.
2. Проверка: сервер подписывает запрос токена и запрашивает список приложений `GET /public/v1/application`; печатается число приложений, доступных ключу. Отказ в токене (неверный keyId или ключ, ключ отключён) и отказ в доступе к методу (у ключа не отмечен метод или приложение) различаются в сообщении. `--no-verify` пропускает проверку.
3. Ключ сохраняется в системное хранилище, заменяя прежний; если проверка не прошла, ничего не сохраняется. Новый профиль создаётся с доступом только на чтение; `--package` записывает имена пакетов, остальные настройки профиля не меняются.
4. В терминале команда предлагает удалить исходный файл ключа (по умолчанию — нет).

### auth status

```text
rustore-mcp auth status [--profile <имя>] [--no-verify]
```

Показывает профиль, ключ (замаскированный keyId и размер RSA, без значения), результат проверки (`Check`: получение токена и запрос списка приложений; с `--no-verify` — без запроса), имена пакетов, клиент, в котором профиль зарегистрирован через `connect`, разрешены ли запись и удаление, наборы инструментов и путь к `profiles.toml`. Если проверка не прошла, причина печатается в строке `Check`.

### auth logout

```text
rustore-mcp auth logout [--profile <имя>] [--forget]
```

Удаляет ключ профиля из системного хранилища. С `--forget` также удаляет настройки профиля из `profiles.toml`. Если ключ больше нигде не нужен, удалите его и в консоли RuStore («Компания → RuStore API»).

## tools

```text
rustore-mcp tools list [--tools-file <путь>]...
rustore-mcp tools check [--tools-file <путь>]...
```

Работают с [пользовательскими инструментами](tools.md#пользовательские-инструменты). Файл пользователя `tools.toml` рядом с `profiles.toml` читается всегда, если он есть; `--tools-file` добавляет те же файлы, что и у `serve`. К API команды не обращаются, ключ не нужен.

- `tools list` печатает таблицу: имя, уровень доступа, операция, фиксированные аргументы, есть ли фильтр `jq`, файл. Инструменты выше уровня доступа сервера при запуске не регистрируются.
- `tools check` проверяет файлы так же, как `serve` при запуске (TOML, поля, операции, фиксированные аргументы по схеме операции, фильтры `jq`, совпадения имён), и печатает для каждого файла `OK` и число инструментов. Ошибка — код выхода не 0 и сообщение с файлом и инструментом.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `RUSTORE_MCP_CONFIG_DIR` | Каталог с `profiles.toml` и `tools.toml` вместо `~/.config/rustore-mcp`. |
| `CODEX_HOME` | Каталог конфигурации Codex для `connect codex` вместо `~/.codex`. |
| `RUST_LOG` | Уровень логов `serve` в stderr, если не задан `--log-level`. |

Ключ RuStore API из переменных окружения не читается никогда.

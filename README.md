# rustore-mcp

MCP-сервер и CLI для [RuStore API](https://www.rustore.ru/help/work-with-rustore-api). Даёт Claude Code, Codex и другим MCP-клиентам работать с кабинетом разработчика RuStore: приложения, версии и публикация, загрузка APK и AAB, тексты карточки, иконка и скриншоты, отзывы и рейтинг, платежи и подписки, продуктовый каталог, доступы пользователей.

- **Все методы RuStore API — MCP-инструменты.** 52 операции в 8 наборах генерируются при сборке из спецификации, собранной по справочнику RuStore API: приложения, версии и публикация, иконка и скриншоты, отзывы, платежи и покупки, подписки, продуктовый каталог, доступы; для платежей и подписок есть варианты песочницы. `api_search` находит нужную операцию (по-английски или по-русски), `api_request` вызывает любую в пределах уровня доступа.
- **Составные инструменты** делают за один вызов то, что в API требует нескольких шагов: поиск приложения (`search_apps`), сводка версий (`release_summary`), загрузка сборки в черновик (`upload_build`), отправка на модерацию (`release_submit`), публикация и поэтапная раскатка (`release_rollout`), экспорт и применение текстов карточки, в том числе перенос из Google Play (`listing_export`, `listing_apply`), синхронизация скриншотов с каталогом (`sync_screenshots`), сводка и выгрузка отзывов (`reviews_summary`, `reviews_export`), отчёт по платежам (`payments_report`), сводка каталога продуктов (`catalog_summary`), сводка доступов по кабинету и изменение роли в нескольких приложениях (`access_summary`, `access_apply`).
- **Ожидание модерации и подсказки MCP.** `wait_for_moderation` ждёт итога модерации версии и сообщает о ходе ожидания, а подсказки MCP (prompts) задают готовые сценарии: выпуск версии, разбор отзывов с черновиками ответов, сверка платежей и проверка всех приложений кабинета. Подробнее — в [docs/tools.md](docs/tools.md#подсказки).
- **Push-уведомления — по желанию.** Набор `push` (выключен по умолчанию) отправляет уведомления на устройство и в топик и управляет подписками на топики через Push API RuStore: 4 операции со своими учётными данными — проектом push и сервисным токеном (`rustore-mcp auth push login`).
- **Ключ — только в системном хранилище.** Ключ RuStore API (keyId и приватный ключ RSA) лежит в Keychain (macOS), Secret Service (Linux) или Credential Manager (Windows) и не читается из переменных окружения и аргументов командной строки (единственное исключение — файл секрета в HTTP-режиме). Токен доступа сервер получает сам и держит только в памяти процесса. Один профиль — один ключ одной компании.
- **По умолчанию только чтение.** Изменения черновика и действия с последствиями для пользователей и денег включаются явно; инструменты выше разрешённого уровня агенту не видны.
- **Секреты не попадают к агенту.** Ключи, токены и подписи вырезаются из ответов и ошибок.

Обычно сервер работает через stdio: MCP-клиент сам запускает `rustore-mcp serve`. Для клиентов без локального бинарника и одного сервера на несколько агентов есть HTTP-режим (`serve --http`, в том числе в Docker): ключ остаётся на сервере, клиенты приходят с токенами доступа — [docs/http.md](docs/http.md).

## Установка

### Установочный скрипт (Linux и macOS)

```bash
curl -fsSL https://codeload.sourcecraft.tech/filipov-dev/rustore-mcp/tarball/refs/heads/install | tar -xzO | sh
```

Скрипт ставит последнюю версию в `~/.local/bin` без `sudo` и сверяет архив с `SHA256SUMS` релиза; повторный запуск обновляет бинарник.

### Homebrew (macOS и Linux)

```bash
brew tap filipov-dev/tap https://git.sourcecraft.dev/filipov-dev/homebrew-tap.git
brew install filipov-dev/tap/rustore-mcp
```

### Windows и готовые архивы

Архивы — на [странице релизов](https://sourcecraft.dev/filipov-dev/rustore-mcp/releases): macOS (универсальный, подписан и нотаризован), Linux x86_64 и aarch64 (статические, без зависимостей), Windows x86_64 (`rustore-mcp-<тег>-windows-x86_64.zip`, без подписи кода: SmartScreen может предупредить при первом запуске). Параметры скрипта, проверка контрольных сумм, установка в Windows, сборка из исходников, обновление и удаление — в [docs/install.md](docs/install.md).

## Быстрый старт

1. Создайте ключ RuStore API (один раз): в консоли RuStore откройте «Компания → RuStore API», создайте ключ, отметьте методы API, которые нужны агенту, и приложения, с которыми он может работать, и сохраните приватный ключ в файл — консоль показывает его только при создании. Файл — JSON `{"keyId": "…", "privateKey": "…"}` или только приватный ключ (тогда keyId передаётся флагом `--key-id`). Подробнее — [ключ RuStore API](docs/cli.md#ключ-rustore-api).
2. Подключите сервер к клиенту:

   ```bash
   rustore-mcp connect claude-code --key-file ~/Downloads/rustore-key.json
   # или
   rustore-mcp connect codex --key-file ~/Downloads/rustore-key.json
   ```

   `connect` проверит ключ (получит токен и запросит список приложений), сохранит его в системное хранилище и после подтверждения зарегистрирует сервер `rustore`. В конце он предложит удалить исходный файл ключа. Перезапустите клиент.

3. Попросите агента, например: «Покажи мои приложения в RuStore и что сейчас на модерации».

Ключ можно сохранить и отдельно: `rustore-mcp auth login --key-file ~/Downloads/rustore-key.json`. Какие разделы API и приложения доступны ключу, покажет `rustore-mcp auth check`. Для Gradle-плагина публикации RuStore и fastlane ключ отдаётся временным файлом: `rustore-mcp key exec -- <команда>` ([справочник CLI](docs/cli.md#key-exec)). Для ключа другой компании заведите отдельный профиль: `rustore-mcp connect codex --profile partner --key-file <файл>` — сервер в клиенте будет называться `rustore-partner`. Другие клиенты и ручное подключение — [docs/clients.md](docs/clients.md).

## Уровни доступа

| Уровень | Как включить | Что доступно |
| --- | --- | --- |
| Чтение | по умолчанию | Только инструменты, которые читают данные: приложения, версии и их статусы, отзывы и рейтинг, платежи, подписки, каталог, доступы, сводки и экспорт. |
| Запись | `--allow-write` | Изменения черновика версии: создание и удаление черновика, тексты и настройки, загрузка APK и AAB, иконка и скриншоты (`upload_build`, `listing_apply`, `sync_screenshots`). Пользователи ничего не видят, пока версия не пройдёт модерацию и не будет опубликована. |
| Удаление | `--allow-destructive` (включает запись) | Удаление и действия с последствиями для пользователей и денег: отправка на модерацию (`release_submit`; при автоматической публикации это выпуск), ручная публикация и процент раскатки (`release_rollout`), архивирование версии, публичные ответы на отзывы, возвраты, отмены и подтверждения покупок и подписок, выдача и отзыв доступов, отправка push-уведомлений (набор `push`). |

```bash
rustore-mcp connect claude-code --allow-write
```

Инструменты выше разрешённого уровня не регистрируются: агент их не видит и не может вызвать. `--toolsets` выбирает разделы API: по умолчанию `apps`, `releases`, `reviews`; `--toolsets all` включает все. Уровень доступа сервера не расширяет права ключа: RuStore всё равно проверяет методы и приложения, отмеченные у ключа в консоли. Подробнее: [docs/tools.md](docs/tools.md).

## Безопасность

- Ключ принимается только из файла (`--key-file`) или stdin (`auth login --key-stdin`) и хранится только в системном хранилище; ни одна команда его не печатает, в конфигурацию MCP-клиента попадает только команда `rustore-mcp serve --profile <профиль> …`.
- Токен доступа живёт в памяти процесса и уходит только в RuStore API; ключа и токена нет в аргументах инструментов, заголовок `Public-Token` агент переопределить не может.
- Сервисный токен push хранится там же, отдельно от ключа, принимается только из файла или stdin (`auth push login`) и уходит только на хосты Push API RuStore; push-токены устройств в ответах скрываются.
- Ключи, токены, подписи и похожие на них значения заменяются на `[redacted]` во всех ответах, включая ошибки.
- Локальные файлы — только в рабочем каталоге сервера, временном каталоге и каталогах из `--allow-path`; существующие файлы не перезаписываются.

Подробнее — [docs/security.md](docs/security.md).

## Чего нет в RuStore API

Создать приложение и ответить на анкеты можно только в консоли RuStore. Статистики и Remote Config в публичном API нет. Процент поэтапной раскатки RuStore умеет только увеличивать.
